# Framed fullscreen

The controller fullscreen button and the video pane's original plus button now fill the current monitor while retaining the skin border. Click either again to restore the pane's previous size and position. The two-button video header and all original normal, hover and pressed assets remain intact; no third icon was added. Video idle backings are flattened over matching source header crops before native caching to preserve their intended composition; see VIDEO-REPAINT.md.

Double-click the video itself for VLC's native borderless fullscreen. Double-click again to leave it. No input overlay intercepts the video. These two modes are independent: leaving borderless fullscreen returns to the framed pane, including its maximized state if selected previously.

The buttons use `Checkbox state="video.isMaximized"`, `video.maximize()` and `video.unmaximize()`. The controller also shows the video window. Both Checkbox states reuse the same original feedback resources. Windows Skins2 maximize uses the nearest monitor's full rectangle, including the taskbar area. The video layout allows up to 8192x4320; frame geometry stays at the selected 1x/2x scale. Only video exposes maximize because VLC shares one saved restore rectangle among skin windows. Restore geometry lasts for the current session; it is not a persistent window history.

Offline checks cover source artwork, both toggle actions, packaged XML, frame/control clearance and monitor-size bounds. Targeted native tests passed for both scales in blue on a 1920x1080 monitor: video plus-button maximize/restore while idle and playing, video double-click into/out of borderless fullscreen, and stopped header appearance. Saved pane positions and sizes were restored. Other monitors/palettes and full native parity remain outside this pass. The tests used separate companion profiles and restored its normal profile afterward. Restart the companion or reload the updated standalone skin to use it. Exact hashes are in fullscreen-review.json.
